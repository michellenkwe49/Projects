The project operates as an automated document intelligence and financial data extraction pipeline engineered to ingest raw invoices and receipts, parse their contents, and transform unstructured document text into structured tabular data. The core logic is split between an exploratory data processing environment and a deployment-ready web application interface.At the center of the data processing pipeline is the Jupyter Notebook titled Invoices & Receipts AI code.ipynb. This notebook serves as the primary experimentation and execution environment where raw data ingestion, text preprocessing, optical character recognition routines, or pattern matching algorithms are executed. Within this environment, data is cleaned, validated, and formatted into uniform schemas. The workflow inside the notebook handles the heavy lifting of parsing document formats, normalizing date structures, extracting line-item details, and computing financial metrics such as sub-totals, taxes, and final payment amounts.  To make the system interactive and accessible without running raw code blocks manually, the project includes a Streamlit web application located at app.py. This application provides a graphical user interface where users can interact directly with the extraction pipeline. Through the Streamlit interface, users can upload new invoice or receipt files, trigger parsing functions on demand, view real-time execution feedback, and visualize extracted metrics directly in the browser dashboard. The app manages state transitions, file handling, and error logging to ensure smooth user interactions during document processing.  The pipeline is also equipped with structured data storage and batch processing capabilities, demonstrated by the inclusion of batch data files named batch1_1.csv and batch1_2.csv. These CSV files act as pre-processed transaction logs or batch input/output matrices, allowing the system to handle multiple records simultaneously rather than processing documents strictly one by one. They store the aggregated results of parsed invoices and receipts, ensuring that historical extraction runs are preserved, auditable, and easily exportable for downstream financial reporting, database insertion, or integration with external accounting software.  Every component works in tandem to form a complete end-to-end lifecycle: raw documents enter the system via the Streamlit interface, the underlying Python and notebook logic extracts and normalizes the text using automated data workflows, and the processed outputs are systematically recorded and stored within the batch CSV data infrastructure for comprehensive tracking and reporting.
